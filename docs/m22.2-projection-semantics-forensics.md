# M22.2 — Projection Semantics Deep Forensics

## Why M22.2 exists

M22.1 showed that the original M20.2 first-difference taxonomy hid projection
failures inside the nominal filter population. This milestone reconstructs the
three native M20.2 projection cases and the 15 M22.1 projection-causal cases,
then checks projection causality without provider calls or production changes.

The populations are unique by `(benchmark, case_id)`:

| Source | Count |
| --- | ---: |

| M22.1 `PROJECTION_CAUSAL` | 15 |
| Overlap | 0 |

All 18 candidates were retained in the new ledger. Historical labels were not
rewritten.

## Methodology

Projection facts were extracted with SQLGlot, including expression type,
column ownership, aggregate/function facts, arithmetic/cast/CASE flags, alias,
and normalized expression. Output aliases are ignored for semantic comparison;
qualified aliases are normalized to physical table names. Projection order is
retained because the benchmark evaluators can compare result columns
positionally.

For the 15 M22.1 cases, the existing M22.1 confirmed counterfactual evidence
was reused. For the three native cases, a projection-only AST replacement was
executed through M1 and the bounded read-only executor. The BIRD `346`
projection replacement was structurally confirmed because the executor's row
bound prevented complete result equality, while the M20.2 AST showed the
projection as the only difference. Advanced `44` was not projection-causal:
the projection replacement remained wrong, while a separate filter diagnostic
replaced the case's `Private` literal with the reference-equivalent value and
matched. It is retained as `UNDETERMINED` in the projection ledger and
reclassified diagnostically as filter-causal.

Gold/reference SQL and results were used offline only. No provider was
constructed and no SQL was regenerated.

## Recommended next intervention

**TYPED_OUTPUT_FIELD_CONTRACT** is the recommended M23 hypothesis. Eight
confirmed cases involve missing or extra output fields and are the most
coherent bounded projection family. The evidence is counterfactual for all
eight. It is narrower than combining output selection with schema grounding or
aggregation semantics, and it can be tested without changing QueryPlan V1 or
M1.

The next experiment must use a fresh, pre-frozen dataset and provider calls;
the 18 cases here are consumed development evidence. It should compare the
current direct path with one typed output-field intervention, measure controls,
and keep M1 as the execution authority.

## Non-recommendations and claim boundary

M22.2 does not treat all SELECT differences as causal, does not bundle
projection with aggregation or schema fixes, and does not expand QueryPlan
solely from these cases. It does not add a router, agent, judge, repair,
retrieval, memory, prompt change, or production output contract. There were
zero provider calls, zero fresh generations, and zero production changes.
