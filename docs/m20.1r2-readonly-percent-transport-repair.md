# M20.1R2 — ReadOnly Execution Percent Transport Repair

Status: `M20_1R2_READONLY_PERCENT_TRANSPORT_REPAIR_VALIDATED`

## Root cause and repair

M20.1R repaired the `EXPLAIN` submission boundary in `QueryCostGate`. The
same psycopg DB-API placeholder interpretation remained in
`ReadOnlyExecutor._execute_on_connection`, which submitted the accepted
candidate with `exec_driver_sql(plan.normalized_sql)`. Literal percent signs
inside patterns such as `LIKE '%abc%'` therefore failed before PostgreSQL
could execute the query.

`ReadOnlyExecutor` now creates only a transport copy of the already accepted
SQL and doubles percent signs in that copy before `exec_driver_sql`. The
logical `QueryPlan.normalized_sql`, stored candidate, evaluator input, and
audit representation remain unchanged. This is the psycopg literal-percent
escape for this driver execution call shape; it is not SQL rewriting or
benchmark-specific pattern replacement.

The repair is downstream of M1. `SqlSafetyService.plan()` remains the only
authority that admits a candidate, and the executor still uses the same
reader role, read-only transaction, statement timeout, bounded fetch, and
typed execution-error boundary. M1 policy and cost semantics were not changed.

EXPLAIN planning boundary and final read-only execution boundary.
