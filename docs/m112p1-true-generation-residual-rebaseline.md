# M11.2P1 — True Generation Residual Rebaseline

M11.2P1 is an offline, additive diagnostic audit. It starts from the accepted
M11.2P0 checkpoint `a9a08ec3de48ac6c4919b34ac8b53160f4cbbe97` and consumes only
the 53 contract-eligible members of the frozen P3 D cell: 23 FULL cases and 30
CORE cases. The three P0-quarantined cases are excluded from failure evidence.

The audit asks which substantive SQL decision boundaries are positively shown
to fail in the frozen OFF and ON candidates. A structural or textual SQL
difference is not sufficient; attribution requires a question/reference
contract, a material candidate violation, and a frozen family/reason code.
Unsupported equivalence remains unresolved. Multi-label attribution is allowed,
and primary failure is not forced when independent failures coexist.

FULL cases may use question-entitled output behavior. CORE cases are limited to
substantive relational and calculation semantics; P0-masked projection/shape
differences cannot contribute to family support. Pair states describe observed
SQL and failure-boundary relationships only. They do not establish memory
causality.

The failure taxonomy and repeated-boundary gate are frozen before eligible
candidate SQL is exposed. A repeated boundary requires at least 10 either-arm
cases, 5 shared cases, and one recurring specific subreason in 5 cases, with
material evidence and no CORE mask contamination. Passing that gate only
qualifies a family for a later intervention-selection review; it authorizes no
implementation.

The frozen P1 semantic/adaptability labels remain quarantined pending P1R2.
M11.2P1 does not repair P1, P0, the evaluator, references, runtime, M1, M3, or
M4. It performs no provider, database, retrieval, candidate-generation, or
public-benchmark work and does not publish a new accuracy score.

The 53 cases are consumed diagnostic evidence and cannot validate a future
intervention. Any later intervention requires a fresh independent validation
population. If no boundary qualifies, the next review is a fragmentation
review; otherwise the qualifying boundary or boundaries receive a separate
architecture review. M11.2P1 itself selects no technology or intervention.

README freshness is a separate docs backlog item; this milestone does not edit
README.

The completed run found no repeated bounded boundary candidate under the frozen
gate. The only positively attributed substantive family was window semantics
(3 either-arm cases; 2 shared); M1 rejection contributed 4 cases with 1 shared
case. Neither met all gate conditions. Pair comparison recorded 7 identical
candidate pairs and 46 different candidate pairs, without treating either
result as memory causality.
