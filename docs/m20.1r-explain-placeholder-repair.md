# M20.1R — EXPLAIN Driver-Safety Repair

Status: `M20_1R_EXPLAIN_PLACEHOLDER_REPAIR_VALIDATED`

## Root cause

M20.1 identified 35 planning errors as the same defect. The original
`QueryCostGate.explain()` built `EXPLAIN (FORMAT JSON) {sql}` and sent that
string through SQLAlchemy's `exec_driver_sql()`. Psycopg interpreted percent
characters in SQL literals such as `LIKE '%foo%'` as DB-API placeholder syntax,
raising `ProgrammingError` before PostgreSQL received the intended statement.

The smallest reproduction was:

```sql
SELECT name FROM products WHERE name LIKE '%a%'
```

The original EXPLAIN call failed with a psycopg placeholder error.

## Repair

`app/execution/cost.py` now creates an EXPLAIN transport copy with
`sql.replace("%", "%%")`. Doubling percent is the psycopg DB-API literal-percent
form. It is applied only to the EXPLAIN transport string; the candidate is
still parsed and policy-checked unchanged before the cost gate. PostgreSQL
receives the original SQL semantics and the existing JSON estimate parsing,
cost thresholds, read-only transaction, and timeout remain unchanged.

No provider was constructed or called. No M1 policy, QueryCostGate threshold,
`SqlSafetyService.execute()`, prompt, model, evaluator, or benchmark artifact
was changed.

The repaired M1 planning boundary therefore removes the diagnosed defect for

with 0 newly measured result matches and 0 newly measured result mismatches at
the unchanged M1 executor boundary. M20.1's prior 25/35 safe external-executor
estimate remains historical diagnostic context, not a replacement result.

## Security and contract invariants

- M1 parser and AST policy are unchanged.
- Function, object, column, statement, and cost policies are unchanged.
- The EXPLAIN transaction remains read-only and bounded by the existing
  settings.
- No raw SQL bypass was introduced.
- `SqlSafetyService.execute()` was not changed.
- Provider behavior and benchmark generation were not rerun.

## Limitations

M20.1R is a frozen-SQL downstream replay, not a fresh benchmark score. It did
not run BIRD, Defog Classic, or Defog Advanced provider workloads. It proves
the EXPLAIN placeholder defect is removed and that the existing M1 planning
outcomes are otherwise invariant. The unchanged executor's matching percent
transport issue is visible and requires separate authorization if it is to be
addressed.
