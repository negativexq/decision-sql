# M29R.1 — Canonical Plan Acquisition Completion

M29R.1 measures the repaired provider boundary, not a new model or semantic
engine. It keeps `gpt-5.6-luna`, the M29 frozen 18-case order, semantic
evidence, database image, one-call budget, and downstream runtime unchanged.

## Protocol result

The M29R.1 primary used native strict JSON Schema with the deterministic
provider-safe projection of `SemanticQueryPlan`:

```text
18 requests → 18 responses → 18 provider-schema-valid
             → 18 provider-structural-valid
             → 12 canonical Pydantic-valid
             → 7 canonical semantic-plan-valid
```

The seven canonical Pydantic-invalid plans are not provider projection
failures: their errors are cross-field semantic invariants (relationship join
shape or calculation-contract coherence). The remaining semantic validator
failures are likewise intentional model-error evidence. The previous 30
second transport censorship is removed by a fixed 90 second experiment-scoped
timeout; the primary had zero timeouts and zero retries.

## Structural versus semantic boundary

Provider-native strict output enforces names, types, enums, closed objects,
required fields, and supported bounds. The local canonical validator remains
authoritative for relationships, population, grain, fanout, calculation
coherence, and other cross-field semantics. M29R.1 therefore reports these as
separate stages rather than collapsing them into `PLAN_SCHEMA_FAILURE`.

The projection preserves `minLength`, `maxLength`, `minItems`, `maxItems`, and
provider-supported simple patterns. It normalizes `oneOf` to `anyOf`, makes
object properties required for the provider's strict-object rule, and removes
unsupported regex lookaround and metadata keywords. The parity evidence is
generated by `evaluation/audit_m29r1_projection.py` into
`evaluation/fixtures/m29r1_projection_parity.json`.

## Frozen semantic evidence

The provider-free oracle ceiling remains separate:

```text
16 representable; 16 compiled; 16 semantic-valid; 16 M1 accepted;
16 executed; 15 officially correct; 1 evaluator limitation;
2 missing legitimate server-owned relationships.
```

In M29R.1, five generated plans pass semantic validation and M1, execute, and
produce one official correct result plus four official mismatches. One further
semantic-valid plan is blocked by the known missing relationship metadata, and
one is rejected by the existing M1 execution policy. These downstream results
are reported separately from contract acquisition.

## Reproducibility

The primary manifest records the model settings, 90 second timeout, schema and
prompt hashes, case-order hash, database image digest, and zero-retry policy.
Full provider responses remain in the ignored protected local journal; normal
tracked artifacts retain hashes, byte counts, validation stages, and bounded
failure summaries only. No oracle plan, reference SQL, gold result, or hidden
reasoning is sent to the provider.
