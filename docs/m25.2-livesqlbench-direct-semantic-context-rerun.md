# M25.2 — LiveSQLBench DIRECT semantic-context paired rerun

## Objective

M25 measured the frozen 18-case DIRECT pilot with GPT-5.6 Luna and one SQL
provider request per case, but M25.1 showed that its context contained raw
integer knowledge references rather than the official direct baseline's
semantic annotations. M25.2 measures the same frozen cases with only that
context corrected.

The old M25 arm is immutable evidence: 1/18 official raw correct. M25.2 does
not rerun it.

## Experimental design

The pilot IDs and order are inherited from the frozen final manifest. The
provider, model, production generation message builder, temperature, reasoning
setting, M1, executor, and evaluator remain unchanged. The new arm uses the
existing DIRECT service and appends the deterministic M25.1 semantic-resource
rendering: live structural schema, all database column meanings, and all
database KB records. Protected per-case references are diagnostic only and do
not filter the model context.

There is one provider SQL call per case, no retry, and no repair, planner,
ResultShape, QueryPlan, judge, router, or second model call. A separate ignored
M25.2 journal prevents duplicate calls on resume.

## Preflight and leakage boundary

Before call one, all 18 corrected contexts and provider messages are built
offline and hashed. Provider-visible input contains the question and corrected
semantic context only. Gold SQL, test cases, reference results, M25 output, and
M25 status are not provider inputs. The full 180-case benchmark is not run.

## Results

The committed result fixture contains aggregate pipeline, paired-transition,
usage, latency, and protected-data-safety metadata. Case-level SQL, context,
and reference details remain below the ignored protected results directory.
The official score uses the unchanged LiveSQLBench evaluator, including its
empty-result behavior. A secondary 17-case reference-valid diagnostic is not
the official score.

The fresh arm completed with 18 Luna calls, 18 provider successes, 18 SQL
proposals, 13 M1 accepts, 13 successful executions, and 6/18 official raw
correct. Against the frozen M25 arm's 1/18, the paired transitions were:

| transition | cases |
|---|---:|
| old correct → new correct | 0 |
| old correct → new wrong | 1 |
| old wrong → new correct | 6 |
| old wrong → new wrong | 11 |

The net paired change is +5 correct cases. The exact two-sided McNemar
binomial p-value is 0.125 (7 discordant pairs); this small pilot is evidence
of transfer, not a full-benchmark estimate. The old correct case was not
preserved, so the result is best described as positive but not regression-free.

The corrected context had median 51,854 characters / 12,964 approximate tokens
(P95 66,310 / 16,578; maximum 69,379 / 17,345). Luna reported median input
usage of 13,212 tokens and total input usage of 239,429 tokens. Provider
latency was median 3,076 ms, P95 4,904 ms, maximum 9,674 ms.

## Claim boundary

This is a paired 18-case intervention measurement. It does not establish a
full 180-case score, production promotion, or causal semantic root causes
beyond the isolated semantic-context change.

## Classification

`M25_2_LIVESQLBENCH_SEMANTIC_CONTEXT_PAIRED_RERUN_COMPLETED` is valid only when
the 18 frozen cases receive at most one request each, the configuration and
prompt remain unchanged, the payload firewall passes, and the output is
accounted exactly.

## Interpretation

This is `POSITIVE_TRANSFER`: semantic context changed actual end-to-end
correctness on five net paired cases and produced six recoveries, but also one
regression. It does not justify a full 180-case run automatically; the next
decision must review whether this small paired result warrants that cost.
