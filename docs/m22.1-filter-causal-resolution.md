# M22.1 — Causal Resolution of Filter Residuals

## Why M22.1 exists

M22 reported 61 nominal `FILTER_SEMANTICS` residuals, but only 22 had an
explicit review. The remaining 39 became `UNDETERMINED` because the analysis
used `REVIEW.get(..., {})`, not because each case had been exhaustively
resolved. M20.2 also used a first-difference ordering, so a WHERE difference
did not prove that filtering caused the wrong result.

M22.1 corrects that limitation without changing any production behavior.

## Frozen population and method

The inputs are the frozen M20.2 and M22 artifacts. No model/provider calls,
SQL regeneration, prompt change, M1 change, or production change was made.
The 39 defaulted cases were all explicitly processed. Six previously reviewed
LOW/MEDIUM-confidence cases were also rechecked. The 16 explicit HIGH-confidence
M22 cases were retained in the revised 61-case ledger as observational evidence;
they were not relabelled as counterfactually confirmed.

Counterfactuals were AST-built with SQLGlot, passed through the existing M1
planner and bounded read-only executor, and evaluated offline against the
frozen reference. The reference SQL/result was never runtime input.

## Counterfactual evidence

Across the 45 diagnostic cases (39 unresolved plus six non-HIGH-confidence
reviews), 19 single-component fixes and three multi-component fixes matched
the frozen reference result. There were 23 non-fixes. The tested dimensions
were FILTER (45), PROJECTION (45), AGGREGATION (17), ORDER_LIMIT (21),
ARITHMETIC (5), DISTINCT (6), SUBQUERY (9), and WINDOW (1). Some candidates
were not executed because M1 rejected the diagnostic hybrid; these are not
treated as evidence of semantic equivalence.

Representative confirmed cases include `16`, `138`, `147`, `250`, `288`,
`297`, `333`, `356`, `397`, `427`, `459`, `490`, and `classic:20`.

## Solution-family mapping and recommendation

The strongest narrow recommendation is **EVIDENCE_APPLICATION_CONTRACT** for
the three counterfactually supported/explicit mapping failures (`122`, `123`,
`125`). Their correct mapping was already present in legitimate input evidence,
so database lookup would not address the causal defect. A future experiment
could test a deterministic typed evidence/predicate handoff without changing
M1 or making evidence an authority.

The two discovery cases support bounded DB value grounding as a separate,
smaller direction. The four normalization cases support deterministic string
normalization, but not a claim that lookup is necessary. The 23 unresolved and
20 non-filter-causal diagnostic cases are not sufficient to justify a broader
filter architecture.

## Non-recommendations

M22.1 does not treat all 61 cases as filter failures, does not assume all nine
wrong-value cases require DB lookup, and does not promote regex constraint
signals into a runtime contract. It does not rerun the 774-case benchmark,
modify prompts, add retrieval, memory, QueryPlan, Window IR, M1 behavior,
repair, judge, routing, or benchmark-specific rules.
