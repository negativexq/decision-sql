# M11.2P3 — Bounded Counterexample Component Isolation

M11.2P3 adds an evaluation-only AST substitution harness over the frozen,
validated M11.2P2 PostgreSQL counterexample engine. For each witnessed arm it
constructs repair and transfer hybrids for changed supported components, checks
round-trip fingerprints and non-target invariance, then compares the hybrids on
the frozen D2 fixture bank.

The strongest result is
`BIDIRECTIONAL_COMPONENT_WITNESS_ISOLATED`. It means only that a component
carried the observed candidate/reference behavioral difference on the governed
fixtures in both substitution directions. It is not universal SQL causality,
equivalence proof, or a memory-effect claim. Unsafe, dependent, interacting,
unsupported, inconclusive, and P0-unentitled substitutions abstain.

The independent D3 controls are executed before the consumed historical
population. Historical shadow is restricted to the 31 pair-level cases that
had an independently witnessed D2 result and frozen multidimensional
structural evidence. The single-dimensional witnessed case and seven unwitnessed
pairs are excluded from the primary population.

The D2 engine, typed results, semantic hashing, fixture bank, M1 admission, and
comparison contracts are reused without modification. Hybrid SQL is diagnostic
AST substitution, not candidate generation. No generation-side intervention is
implemented here.

The LLM proposes. Deterministic software decides what may execute. Don’t
improve what looks suspicious. Improve the decision boundary the evidence proves
is failing.

Implementation and measurement are the default after a bounded mechanism has
passed selection. Unresolved cases abstain. A failed implementation gets fixed
or removed. A validated diagnostic result leads to the next bounded
implementation. Do not repeatedly reopen mechanism selection.

Once a repeated bounded component is independently isolated, stop diagnosing it
and implement the bounded generation-side intervention.
