# M25.3 — Frozen Pilot Failure Resolution

## Motivation

M25.2 measured the corrected semantic-context arm on the frozen 18-case
LiveSQLBench pilot. It produced 6/18 official correct results, with five
queries stopped by M1 and seven accepted queries executing to an official
result mismatch. M25.3 replays those exact persisted SQL strings without a
provider call and separates deterministic infrastructure behavior from the
generated SQL's semantics.

The historical M25.2 score remains 6/18. The replay below is
`FROZEN_OUTPUT_PROVIDER_FREE_REPLAY`, not a new model score.

## Failure ledger and method

The twelve M25.2 failures were retained in the ignored protected results
area. The ledger contains the original runtime inputs, generated SQL,
reference SQL and result evidence locally, while the committed artifact only
contains aggregate and safe stage metadata.

Each failure received one primary class. The five M1-stage failures were
examined first. The seven accepted/executed mismatches were then compared
against the offline reference execution, with bounded counterfactual reasoning
used only to identify causal mechanisms. No generated SQL was rewritten for
scoring.

## M1 failure analysis

Three failures used PostgreSQL's read-only JSONB text extraction operator
(` #>> `). SQLGlot represents that syntax as `JSONBExtractScalar`, normalized
by the policy to `JSONB_EXTRACT_SCALAR`. The existing reviewed analytical
surface omitted that representation even though the operation is pure,
read-only text extraction. It was added to the general string-function family.

The archeology `UNKNOWN_COLUMN` query references a column PostgreSQL reports as
absent (`s.zoneref`); its rejection is correct and no scope resolver change was
justified. The vaccine query reaches PostgreSQL's unsupported
`round(double precision, integer)` signature; this is invalid generated SQL,
not an M1 planner defect.

## Deterministic fixes

The only M1 change is the general allowlisting of SQLGlot's
`JSONB_EXTRACT_SCALAR` representation. Synthetic coverage verifies that it is
accepted while `RANDOM`, `CLOCK_TIMESTAMP`, `PG_SLEEP`, `SET_CONFIG`, and
unknown functions remain rejected. The full SQL safety and PostgreSQL suites
remain required controls.

The semantic-context renderer also had a generic duplicate-record defect: it
converted the complete KB to a dictionary keyed by the non-unique knowledge
name. It now renders all records in stable ID order. This did not establish a
causal connection to any frozen pilot failure, but it is a required general
context-integrity repair.

No M1 implementation defect, execution wrapper defect, evaluator change, or
benchmark-specific rule was introduced. The historical BIRD/Defog replay was
not run because those database roots were unavailable.

## Executed mismatches

The seven originally accepted/executed mismatches remain semantic failures in
the frozen replay. Their local evidence shows generated SQL that differs in
meaning, including unnecessary joins or population changes, missing filters
or ranking constraints, incorrect snapshot selection, aggregation over the
wrong population, numeric precision/formula differences, and use of a
performance timestamp where the requested current-date age was required.
These are model-semantic failures, not automatic proof of a missing Decision-
SQL capability. Two of the seven involve multiple independently material
semantic changes; they remain one primary `MODEL_SEMANTIC_FAILURE` ledger
class with multi-mechanism secondary notes.

The duplicate KB record was not used to attribute a pilot failure. The two
column-meaning mismatches found previously are public-resource metadata drift
(`clinleadref`/`leadclin` and `hallrecord`/`hallregistry`), not a case-specific
matching bug; no fabricated meanings were added.

## M25.2 → frozen replay

With `JSONB_EXTRACT_SCALAR` reviewed and allowed, the three function-blocked
SQLs become executable, but none becomes officially correct. The replay is:

| Stage | M25.2 | Frozen replay |
| --- | ---: | ---: |
| M1 accepted | 13 | 16 |
| M1 blocked | 5 | 2 |
| execution success | 13 | 16 |
| official correct | 6 | 6 |
| official mismatch | 7 | 10 |

The one empty temporal reference case remains an official evaluator
limitation under the unchanged evaluator. The 180-case provider-free gold
replay remains 175 M1-compatible, with one cost rejection and four intentional
multi-statement rejections; all 175 accepted references execute successfully.

## True residual

At the pipeline stage, two frozen generated queries remain correctly blocked by
M1 because PostgreSQL rejects their references/signatures. At the root-cause
level, the eleven non-reference-limited failures are generated-SQL semantic
failures, while one is the known empty-result temporal reference limitation.
No evidence supports an evaluator repair or another production safety
expansion in this milestone.

## Security and claim boundary

The following remain unchanged: SELECT-only and single-statement enforcement,
catalog/table/column boundaries, ambiguous-column fail-closed behavior,
unknown-function fail-closed behavior, volatile and stateful-function denials,
cost limits, and read-only execution. Provider calls and fresh generation were
zero.

This milestone demonstrates provider-free remediation and failure accounting;
it says nothing about a new LiveSQLBench model accuracy. M25.2's 6/18 result is
preserved as historical evidence.
